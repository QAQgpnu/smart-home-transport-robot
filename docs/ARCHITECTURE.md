# 架构与决策记录

## 目标

在缺少比赛原始源码和机器人硬件的情况下，保留最有辨识度、最容易审查的算法主线，并让招聘者可以在两分钟内看到运行结果、代码结构和证据边界。

## 关键决策

### ADR-001：重构而不是整理旧备份

旧备份混有厂商软件、第三方示例、构建产物和作者不明代码，直接上传会产生版权、归属和可维护性问题。因此公开仓库只包含重新编写的 Python 标准库实现。

### ADR-002：把 Dijkstra 与 DWA 做成闭环

单独展示最短路不足以体现移动机器人局部决策。重构将全局路径作为参考，由 DWA 在每个控制周期输出速度，使动态障碍出现后仍能继续任务。

### ADR-003：运行结果驱动展示层

README 图、JSON 指标和浏览器动画都由同一次模拟输出生成，避免文档手填数字与代码行为漂移。

### ADR-004：不依赖 ROS 和深度学习框架

比赛计划书包含 ROS、TensorFlow 和视觉方向，但留存证据不足以证明完整落地。当前版本以 Python 标准库实现导航核心，使任何评审者无需硬件和大型依赖即可运行。

### ADR-005：最低限度检查，不伪装完整测试体系

仓库没有构造大量形式化单元测试。自动化只重新执行确定性演示并确认目标到达与派生文件存在，名称明确为 `demo-smoke`。这与当前作品集“展示优先、保持基本可运行”的目标一致。
