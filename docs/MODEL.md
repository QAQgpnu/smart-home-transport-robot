# 导航模型说明

## 1. 全局规划

环境被离散为 24 × 16 的占用栅格。节点与上下左右邻居之间的代价为 1，与对角邻居之间的代价为 `sqrt(2)`。Dijkstra 使用优先队列维护当前累计代价：

```text
g(next) = g(current) + movement_cost
```

对角移动只有在两个相邻正交单元都可通行时才允许，避免路径从障碍物角点穿过。

## 2. 动态窗口

机器人状态为 `(x, y, yaw, v, w)`，控制周期为 0.2 s。每轮先根据当前线速度与角速度、最大加速度和最大角加速度构造可达速度窗口：

```text
v ∈ [max(0, vₜ - aᵥΔt), min(vmax, vₜ + aᵥΔt)]
w ∈ [max(-wmax, wₜ - a𝑤Δt), min(wmax, wₜ + a𝑤Δt)]
```

在窗口内离散采样 7 个线速度和 13 个角速度，并使用差速运动学前向预测 1.4 s：

```text
xₜ₊₁   = xₜ + v cos(yaw) Δt
yₜ₊₁   = yₜ + v sin(yaw) Δt
yawₜ₊₁ = yawₜ + w Δt
```

## 3. 碰撞过滤与评分

如果候选轨迹上任一点的障碍物净间距小于机器人半径 0.34 m，整条轨迹被淘汰。其余轨迹使用以下加权代价：

```text
J = 2.2 × target_distance
  + 1.0 × path_distance
  + 0.55 × heading_error
  + 0.75 / clearance
  + 0.35 × (max_speed - speed)
```

- `target_distance`：预测终点到前视目标的距离；
- `path_distance`：预测终点到全局路径的最近距离；
- `heading_error`：预测朝向与目标方向之差；
- `clearance`：候选轨迹的最小障碍净间距；
- `speed`：鼓励在安全情况下提高推进速度。

这套权重用于展示不同目标之间的工程折中，不声称来自比赛实机标定。

## 4. 场景与结果

默认场景包含外墙、四组家具、一道带门洞的隔断和一个在第 36 控制步出现的圆形障碍。固定场景、固定采样顺序、无随机数，因此重复运行应生成相同轨迹和指标。

`artifacts/navigation-run.json` 是权威运行输出；README 和 SVG 中的指标均来自该文件。

## 5. 与真实机器人的差异

- 二维圆形质点不能描述双足机器人的支撑多边形、步态、滑移和跌倒风险；
- 障碍物位置是理想真值，不经过相机、雷达或 SLAM；
- 不包含 ROS 消息、实时线程、串口/Wi-Fi 通信和执行器控制；
- 不估计模型误差、控制延迟、电机死区和电池状态；
- 没有比赛原始参数，因此只能验证算法链条的可运行性，不能比较复现精度。
